## Collector processor placement (for the paper's description)

The priority processor is one collector component, same package and factory, deployed at two pipeline positions: `priorityotlp receiver → priority (admission) → batch → priority/queue → exporter`.
- **Admission stage (first):** enforces the memory thresholds, refuses LP by class, and evicts the LP waiting in the queue stage once the heap reaches the shed line.
- **Queue stage (after batching):** replaces the exporter's own sending queue. It never refuses and never evicts checkpoints.
- **The receiver:** consults the same admission state to refuse LP before decoding.
- **Nothing outside the processor module is modified.** `batch` and the OTLP exporter are upstream core, and the ClickHouse exporter is unmodified. The config-discovery receiver, which serves the checkpoint range and reverse policy to the SDK, runs on its own separate pipeline.
